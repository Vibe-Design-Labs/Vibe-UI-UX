# AI 编写新效果与故障诊断

版本 `0.4.4.0.0`，本轮交付待审 PR；合并与 Pages 部署成功后才成为官网能力。

## 两条明确不同的流程

- **理解并匹配配方**：无密钥时本地解析；有密钥时模型生成 Design IR，然后在已有五类配方内匹配。这个流程不会写新代码。
- **让 AI 编写新效果**：使用用户自己的 TokenDance 密钥，向选定的对话模型发送代码生成请求。模型实际返回 HTML、CSS、JavaScript 与可调参数，不依赖词库 ID 或已有配方。无法保证所有模型都能一次返回有效实现。

“查找效果”仍只查已知词条。“本地试试”与 JSON 导入、重播、参数调整、导出均不调用模型。单次点击只有一次付费请求，不自动重试；取消、超时或结果校验失败仍可能已经产生服务商费用。

## 用户操作

1. 打开工作台，连接 TokenDance，选择支持 `openai:chat-completions` 的模型。密钥仍只保存在本页内存。
2. 描述一个具体效果，例如“鼠标移动时，一圈墨点形成的星图向指针弯曲，可以调整墨点大小和颜色”。点击 **让 AI 编写新效果**。
3. 新区域展示实际返回的代码与独立预览。只有结构校验通过、模块运行并返回控制器后才显示“预览已运行”。这不代表视觉质量、语义或资源开销已经人工验收。
4. 操作预览并调参，展开 **查看实际源码**。描述中的行为由模型提供，参数清单从实际参数对象生成；需核对代码、行为与说明是否一致。
5. 选择 **导出 Web 源码 ZIP**。包中包含 `effect.html`、`effect.css`、`effect.js`、`effect.json`、隔离运行时和示例。运行 `python -m http.server 4180`，打开 `http://localhost:4180/`，无需密钥。
6. 用 **导出效果 JSON** 保存当前源代码和参数。之后可从工作台 **导入效果 JSON** 本地恢复；维护者也可导入 PR 中的案例 JSON。
7. 满意后点击 **申请收录 · 待审 PR**，填写可选署名并确认公开代码与 MIT 许可，在 GitHub 确认 Issue。机器人提取代码数据，创建独立分支上的真实 PR。维护者审核合并前，main、官网与其他用户工作台保持原样。

新生成代码本轮提供原生 Web 包。已有五个受控模板继续提供 Web / React / 视频导出；不要把生成代码的 Web 包称作已完成 React 或视频适配。

## 状态为什么失败

旧版把所有异常合成“AI 连接或结果验证失败”，无法判断实际阶段。新版区分：

| 状态 | 含义 |
| --- | --- |
| network | 请求未获得可读的服务响应；可能是网络或 CORS，不代表服务商一定没收到请求 |
| timeout | 等待超时，无法确认服务端是否已执行 |
| cancelled | 用户取消或切换状态，本次结果不会再应用 |
| auth / limit / model | 已收到服务拒绝，分别检查授权、余额/限额、模型或请求参数 |
| response-json | 已收到 HTTP 响应，但响应体不可读、超过大小限制或不是有效 JSON |
| empty | 服务响应中没有可用模型正文，不能直接声称模型已完成 |
| truncated | 模型返回 `finish_reason: length/max_tokens`，输出被截断 |
| json | 模型正文已返回，但正文 JSON 无效 |
| schema | 正文已返回，但结构、证据、参数或代码边界未通过校验 |
| unsafe | 正文包含回显密钥或不可公开的凭据信息，已拒绝 |
| runtime | 代码已返回，但隔离预览未初始化、更新失败或运行报错 |

仅保留固定诊断类别、是否收到服务响应和 HTTP 状态，不展示网关原始报错、请求头、凭据。没有后台日志可以据截图追溯旧请求的实际失败原因；若继续发生，界面阶段信息可帮助定位。

## 代码契约与运行边界

`public/generated-core.js` 是客户端、服务端、投稿与构建的共同契约。代码使用以下原生模块入口：

```js
export default function mount(root, params, {reducedMotion}) {
  // root 已挂载 HTML。使用 params 作为可调值来源。
  return {
    update(nextParams) { /* 实际应用新参数 */ },
    dispose() { /* 删除监听并取消动画和计时器 */ }
  };
}
```

最多 8 个数字、颜色或布尔参数；HTML / CSS / JS 与整个 JSON 有长度上限。拒绝外部资源、联网 API、存储、导航、跨窗口访问等明显越界内容。静态检查是边界检查，不能证明任意代码安全、描述准确、每个参数有效或资源消耗合理。

代码只在 `sandbox="allow-scripts"` 的独立文档中运行，不开放 `allow-same-origin`、弹窗、表单或顶层导航。文档 CSP 禁止联网、外部图片/字体、嵌套帧和 Worker。父页面只通过专用 MessageChannel 传递代码与有效参数，不传入密钥。父页面不 eval 模型代码，不开放由模型定义的主页面操作接口。隔离不等于 CPU 资源配额；无限循环等坏代码仍可能卡住浏览器，不能承诺停止按钮能终止所有同步死循环。

## 投稿如何保存实际代码

参数案例保留 schema_version 1。新代码采用社区提交 / 案例 schema_version 2，`kind: generated`，包含完整 `artifact` 与最终 `params`。机器人身份取真实 GitHub Issue 事件。只写 `community/cases/case-N.json`，代码作为数据保存，Actions 不导入、不运行投稿 JS；页面上的预览始终使用隔离运行时。

为了减少 URL 过长，将白名单数据 gzip + base64url 放进一个 `intentkit-gzip` 块；解压流限制到 65,000 字节，拒绝混合 / 重复块。编码是传输方式，不是加密，投稿后的代码公开可见。若 URL 超过 7,800 字符，提供“复制完整投稿内容”，用户在 GitHub 正文中粘贴后确认，不丢失代码、不改用占位案例。

维护者先看 JSON diff 的 HTML/CSS/JS，下载并导入同一案例，核对参数全部生效、输入边界、触摸/键盘、减少动态效果、重播与清理、资源开销、来源与许可。批准检查运行不等于同意收录；人工合并后 Pages 才发布。社区列表里的生成代码需主动点击重播，避免加载列表就同时运行多份任意代码。
